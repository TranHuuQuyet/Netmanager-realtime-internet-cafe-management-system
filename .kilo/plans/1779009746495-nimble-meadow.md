## Issues Found (must be resolved before networking skeleton)

### Issue 1 — Namespace mismatch for `LoginResultPayload` / `LoginFailedPayload`

`LoginResultPayload.cs` and `LoginFailedPayload.cs` declare `namespace NETManager.Shared.Models` but both `PacketFactory.cs` and `PacketTypePayloadTypeMap.cs` reference them through aliased `using` statements. This works at compile time **only if** the using statements are correctly set up. `PacketFactory.cs` imports `using NETManager.Shared.DTOs.ResponsePayloads;` but the records are actually in `NETManager.Shared.Models` — this will produce a **compile error**.

### Issue 2 — Missing `ChatPayload` in `Shared.Models` namespace import path

`PacketFactory.cs` and `PacketTypePayloadTypeMap.cs` reference `ChatPayload` — it exists in `NETManager.Shared.Models`. `PacketFactory.cs` imports `using NETManager.Shared.Models;` so this is fine. `PacketTypePayloadTypeMap.cs` does NOT import `NETManager.Shared.Models` — it only imports `NETManager.Shared.Enums`. This will cause a **compile error**.

### Issue 3 — No networking skeleton exists yet

`Code/ServerApp/` and `Code/ClientApp/` directories are expected per `DOCS/TASKS.md` but there is no TCP listener/connector code. Per the plan below, networking skeleton is the main remaining task for Member 2.

### Step 2 — Create networking skeleton (`Code/ServerApp/`)

- `Code/ServerApp/Models/` — `ClientConnection`, `ConnectedClient`
- `Code/ServerApp/Handlers/IPacketHandler.cs` — interface for type → handler dispatch

### Step 3 — Create networking skeleton (`Code/ClientApp/`)

Create:
- `Code/ClientApp/Services/` — TCP connector, receive loop

- `Code/ClientApp/Handlers/IPacketHandler.cs` — same interface shape as server

### Step 4 — Proof-of-concept connect/send/receive

- Validation: one packet exchanged end-to-end without exception
